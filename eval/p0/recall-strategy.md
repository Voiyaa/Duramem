# P0 召回策略模板（reflective recall，编排层）

> 用途：贴给宿主模型（系统提示 / 工具描述附件），让它在记忆检索上从"单程"升级为
> "检索 → 评估 → 再检索/对比"的环路。设计依据：设计文档 §16（v4 迭代检索环路）。
> 本模板是 P0 评测的执行协议：评测执行者按此模板逐题操作。

---

## 召回策略（可整段内联给模型）

你在有 Duramem 记忆库的环境下工作。回答依赖历史细节的问题时，按以下策略使用
记忆工具（`dm_search` / `dm_read_neighbors` / `dm_read_session` / `dm_read_original`）：

### 第一跳（默认单程检索）

1. 用用户的原始问题（或从中提取的关键词）调用 `dm_search`，`top_k=5`。
2. 通读返回的摘要（L0）与 `_suggestion`。此时先判断：**凭已召回内容能否回答？**
   - 能 → 直接回答，停止。
   - 不能，且出现升级信号 → 进入环路。

### 升级信号（出现任一条即进入环路）

- 召回的摘要与问题相关但明显只覆盖了一半（问题包含两个以上事实点，召回只命中其一）；
- 召回结果里有指向其他会话/时间的线索（"后来""最终""另一次"），但当前内容不含结局；
- 返回了弱结果告警（warnings）或命中数很少；
- 摘要明确说"细节见原文"（`has_original` 或 `_suggestion` 提示）。

### 环路（最多 3 个额外动作）

每跳按需选一个动作，选型规则：

| 情况 | 动作 |
|---|---|
| 召回内容里出现了**新的关键实体/错误码/文件名/决策名**，值得单独搜 | `dm_search`，query = 原问题核心词 + 新实体词 |
| 命中的切片属于某个会话，需要该会话全貌或找同会话其他切片 | `dm_read_session(session_id)` |
| 命中切片的上下文被切断，需要前后相邻切片 | `dm_read_neighbors(uid)` |
| 摘要提到具体数值/原话/错误码但没给出 | `dm_read_original(uid, mode="quote", detail="minimal")`（每题最多 1 次） |

**三条硬规则（防跑飞）：**

1. **锚定**：每一跳的 query 必须仍包含原始问题的核心实体。禁止被召回内容的措辞
   带着越走越远。
2. **去重**：不要重复已经用过的 query（逐字或近义）；已见过的切片 uid 不必再取。
3. **预算**：环路最多 3 跳；`dm_read_original` 每题最多 1 次。用尽即停，
   基于已有召回作答，并如实说明哪部分没有找到。

### 停止条件（任一即停）

- 已召回内容足以回答原始问题；
- 新一跳返回的全是已见过的内容（无新增 uid）；
- 跳数预算用尽。

## P0 评测执行协议（给执行代理的补充规则）

对每道题：

1. **hop 0**：`dm_search(query=<题目原文>, top_k=5, db="Duramem开发")`。
   记录返回的全部 uid（切片与会话命中都要记）、`retrieval_mode`、warnings。
2. 判断是否满足升级信号；满足则按上面策略继续 hop 1..3，每跳记录：
   工具名、实际 query/参数、返回的 uid 列表、一句话说明这跳带来了什么新信息。
3. 全程**不得读取 `eval/p0/questions.md`**（那是答案卷，读即判负）；
   不得凭先验知识作答，只依据工具返回内容。
4. 停止后输出该题的执行记录（JSON 行），格式：

```json
{"qid": "Q01", "hops": [{"n": 0, "tool": "dm_search", "args": "query=...", "uids": ["..."]},
                         {"n": 1, "tool": "dm_read_session", "args": "session_id=...", "uids": ["..."]}],
          "stop_reason": "gain_exhausted | answered | budget", "note": "一句话"}
```

评分（不由执行者做）：hop 0 的 uid 集合 = 单程召回；所有 hop 的 uid 并集 = 环路召回。
